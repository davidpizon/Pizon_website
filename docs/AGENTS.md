# PIZON BBS — agent and contributor guide

PIZON.COM is David Pizon's personal website, presented as a 1990s bulletin board system: dial-up
intro, graffiti ANSI banner, Discord or GUEST login, numbered menus, message board, file areas, door
games and `NO CARRIER` on logoff. This file is the canonical agent file: `CLAUDE.md` and
`.github/copilot-instructions.md` at the repo root are symlinks to it.

## Platform

- .NET 11 (SDK pinned in `src/global.json`), Blazor Web App with **global InteractiveWebAssembly,
  prerendering off**. Every keystroke and animation runs in the browser.
- ASP.NET Core minimal APIs, EF Core + SQLite, SignalR (presence), Discord OAuth2 (scope `identify`).
- The terminal is an 80×25, 256-color ANSI emulator written as plain ES modules (no npm, no bundler).
- .NET Aspire is for **local run and test only**. Production is Docker + Caddy on a Hostinger VPS.

## Quick start

```bash
dotnet run --project src/Pizon.AppHost
```

Opens the Aspire dashboard; the `web` resource links to the site. Without Aspire:
`dotnet run --project src/Pizon.Web` (SQLite at `src/Pizon.Web/App_Data/bbs.db`).

In Development, `/auth/dev?user=tester` or `/auth/dev?user=sysop` signs in a fake local user, so posting,
scores and the SysOp console can be tested without Discord. That endpoint does not exist outside Development.

The single test entry point (build with warnings as errors, all tests, coverage gate):

```bash
pwsh src/coverage.ps1
```

## Build rules (enforced — the build or tests fail otherwise)

1. **All warnings are errors**, in every project including tests: `TreatWarningsAsErrors`,
   `MSBuildTreatWarningsAsErrors`, `AnalysisLevel=latest-recommended`, `EnforceCodeStyleInBuild`,
   NuGet audit (`NuGetAuditMode=all`).
2. **No silent suppressions.** No `NoWarn`, no `WarningsNotAsErrors`, no `#pragma warning disable`.
   The only allowed exceptions are a targeted `[SuppressMessage(..., Justification = "...")]` or a
   commented line in `src/.editorconfig`. EF Core migrations are exempt (generated by `dotnet ef`).
3. **Document every class and public function.**
   - C#: XML doc comments (CS1591 + StyleCop SA1600-series are errors, internal members included).
     Bool properties start "Gets or sets a value indicating whether" (SA1623).
   - Razor: every `.razor` file has a `.razor.cs` code-behind whose partial class has a `<summary>`
     (Razor's generated code hides CS1591, so `Pizon.Conventions.Tests` checks this).
   - JavaScript: a `/** … */` JSDoc block on every function, class, method and exported constant;
     no `var`; every export must be used (checked by `src/tests/js/jsdoc.test.mjs`).
4. **80% coverage**, enforced by `src/coverage.ps1`:
   - .NET: coverlet (`coverlet.collector`, settings in `src/tests/coverage.runsettings`), merged
     across test projects with ReportGenerator; **line and branch** ≥ 80%.
   - JavaScript: Node's built-in coverage; **lines, branches and functions** ≥ 80%.
   - Exclusions are minimal: generated code, EF Core migrations, the AppHost (covered by its smoke
     test) and the door template. Anything else needs `[ExcludeFromCodeCoverage]` **and** a written reason.
5. **Tests live in `src/tests/`.** xUnit v3 runs in VSTest mode (needed by coverlet.collector).
   Test classes and methods get a `<summary>` saying what they prove.
6. JS tests use only Node built-ins and the hand-made fakes in `src/tests/js/support.mjs`. Any
   `console.warn`/`console.error` during a test fails it. Never read Node's built-in `localStorage`
   in a test (it warns, and the warning hangs the run); replace the property instead.

## Working rules

- **Never commit secrets.** `Discord__ClientId`, `Discord__ClientSecret`, `SysOp__DiscordUserId` and
  `Notify__WebhookUrl` go in `dotnet user-secrets` locally and in `~/pizon/.env` on the server.
- **Placeholders are marked `TODO-SYSOP`.** Don't invent personal facts about David; leave the marker.
- Visitor text is untrusted: run it through `PipeCodes.Escape` before mixing it into pipe-code text.
- Every state-changing API call requires the `X-PIZON-BBS: 1` header (CSRF defense with SameSite=Lax).
- Guests (level 0) can read but not post, page the SysOp, save scores, appear in the user list or
  enter `requiresAuth` doors. The server enforces this; UI checks are only for display.
- Commit or push only when asked.
